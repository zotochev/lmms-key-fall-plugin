# KeyFall — тренажёр игры на MIDI-клавиатуре (Tool-плагин LMMS)

Сводный план по итогам четырёх экспертных обзоров: архитектура плагинов LMMS, UI/UX, педагогика, существующие решения.
Метки: **[MVP]** — входит в этапы 1–5, **[v2]** — сразу после, **[later]** — потом.

---

## 0. Ключевые решения

| Вопрос | Решение | Почему |
|---|---|---|
| Версия LMMS | `master`, **зафиксированный коммит** (на момент обзора `bed447b`, 2026-10-25) | stable-1.2 заброшена с 2023 (Qt4/Qt5, только MinGW). В master активное API (`MidiClip`, `TimePos`, `Timeline`), но оно меняется — коммит пиним |
| Qt / сборка | Linux: Qt5 ≥5.15 (по умолчанию). Windows: MSVC + vcpkg + Qt 6.8 (`-DWANT_QT6=ON`) — как в CI LMMS | Код пишем Qt5/Qt6-нейтральным |
| MIDI-вход | Сигналы `InstrumentTrack::midiNoteOn/Off` всех инструментальных треков (на них же работает запись в Piano Roll). До 2026-10-29 был свой `MidiPort` + патч `LMMS_EXPORT` | Патч к LMMS не нужен, переносить на новые версии нечего. Цена: KeyFall слышит только треки с включённым MIDI-входом, контроллеры (CC) не приходят, отпускание при нажатой педали приходит с педалью |
| Отметки времени входа | Ставим **сами** в `processInEvent` (`std::chrono::steady_clock`) | `MidiEvent` не несёт времени; WinMM его отбрасывает, ALSA — частично |
| Время нот | Храним в **тиках** клипа, в мс переводим по локальному темпу | Автоматизация темпа просто меняет скорость прокрутки; сетка тактов остаётся ровной |
| Окна попадания | Гибрид: `clamp(доля_доли × beatMs, minMs, maxMs)` (таблица в §5) | Чистые мс несправедливы на медленном темпе, чистые тики — на быстром |
| Сопоставление нот | Жадное по высоте; для повторяющейся высоты — **самая ранняя несопоставленная** нота в окне (FIFO), не «ближайшая» | Стандарт де-факто (Linthesia/Neothesia); FIFO не даёт одному нажатию «украсть» следующую ноту |
| Синхронизация | QTimer ~16 мс на GUI-потоке читает позицию `Timeline` + интерполяция по `steady_clock`, сброс при скачке/лупе | LMMS обновляет позицию раз в аудиобуфер — без интерполяции картинка дёргается. Критично для MVP |
| Отрисовка | `QWidget` + `QPainter`, кэш клавиатуры в `QPixmap`; `QOpenGLWidget` — запасной путь | Хватает для 60 FPS при аккуратной отрисовке |
| Настройки | `ConfigManager::inst()->value("keyfall", …)` | `saveSettings/loadSettings` у Tool-плагинов никогда не вызываются |
| Лицензия | GPLv2+ как LMMS. Из PianoBooster/Neothesia/Sightread (GPLv3) берём **только идеи и константы**, не код. Код самого LMMS (GPLv2+) брать можно | Иначе плагин в составе LMMS станет GPLv3 |
| Режим ожидания (wait) | Собственные часы KeyFall, транспорт LMMS остановлен; часы стоят, пока не нажат весь текущий аккорд | Программная пауза/продолжение транспорта LMMS ненадёжна и меняет звук. Подход Neothesia |

**Разногласия экспертов и как они разрешены**
- Wait mode: педагог — «самое ценное, MVP», UX — «v2». → Отдельный этап 6 сразу после MVP; scorer и часы проектируем под него с самого начала.
- Окна в мс vs в тиках: → гибрид из педагогической таблицы, считается по локальному темпу ноты.
- «Ближайшая» vs «самая ранняя» нота: → FIFO для одинаковой высоты, ближайшая по времени среди разных нот аккорда.

## 1. Архитектура

```
plugins/KeyFall/
  KeyFall.{h,cpp}          ToolPlugin-модель: владеет MidiInput, настройками (ConfigManager)
  KeyFallView.{h,cpp}      ToolPluginView: тулбар (трек/клип, устройство MIDI, ⚙ настройки: строгость, задержка), компоновка
  ClipSource.{h,cpp}       Адаптер LMMS: перечисление клипов, QPointer<MidiClip>, сборка Chart, отслеживание dataChanged
  TransportClock.{h,cpp}   Позиция Song/Timeline → тики клипа, интерполяция, детект лупа/скачка, latency offset
  MidiInput.{h,cpp}        MidiEventProcessor + MidiPort; SPSC-кольцо {key, vel, on, t_ns}
  FallCanvas.{h,cpp}       Водопад: сетка, полосы нот, «призраки» нажатий, вспышки попаданий
  KeyboardWidget.{h,cpp}   Своя клавиатура: рисует любую раскладку по зонам (piano/grid), §3a
  LayoutRepository.{h,cpp} Загрузка *.kflayout.json (встроенные + пользовательские) → core/KeyboardLayout
  InputResolver.{h,cpp}    Сырой MIDI → PressEvent{controlId?, pitches, state, hand}; для фортепиано controlId = pitch
  layouts/                 Встроенные раскладки (generic-25…88, модели от сообщества)
  core/                    БЕЗ Qt и LMMS → юнит-тесты
    Types.h  Chart.{h,cpp}  Scorer.{h,cpp}  Tolerance.h  Stats.{h,cpp}  KeyboardLayout.{h,cpp}
  tests/
```

**Поток данных**
```
MidiClip ──ClipSource──▶ Chart{tick,len,key,vel}  ────────────┐
Song/Timeline ──TransportClock (16 мс, GUI)──▶ nowTick ────────┼──▶ Scorer ──▶ ScoreState ──▶ FallCanvas / Keyboard / HUD
MIDI-поток ──MidiInput (lock-free push)──▶ GUI-дренаж ──▶ InputEvent{key,on,tick = clock.tickAt(t_ns) − latency} ┘
```

**Потоки:** весь GUI-поток, кроме захвата MIDI (поток драйвера → lock-free SPSC). В аудиопоток не заходим, блокировок движка не берём. `QMetaObject::invokeMethod` на каждое событие не используем — он выделяет память.

**Интерфейс оценки (чистый C++)**
```cpp
struct ChartNote  { int64_t startTick, lenTicks; uint8_t key, vel; uint8_t hand; };
struct InputEvent { uint8_t key, vel; bool on; double tick; };
enum class Grade  { Perfect, Good, Ok, Miss, Extra, Skipped };
struct Judgement  { size_t noteIdx; Grade g; double deltaMs; };

class Scorer {
public:
    void load(std::vector<ChartNote>, TempoMap, Tolerance);
    void reset(double fromTick);                        // старт/скачок/луп: ноты до позиции → Skipped
    std::vector<Judgement> onInput(const InputEvent&);  // FIFO по высоте внутри окна
    std::vector<Judgement> advance(double nowTick);     // просроченные → Miss
    bool requiredChordSatisfied() const;                // для wait mode
    Stats stats() const;                                // Notes %, Rhythm %, bias, σ, по тактам
};
```

**Позиция ноты в песне:** `absTick = clip.startPosition() + clip.startTimeOffset() + note.pos()`, берём ноты с `pos < clip.length() − startTimeOffset` (как в `InstrumentTrack::play`). Режимы воспроизведения: `PlayMode::Song` — абсолютная позиция; `PlayMode::MidiClip` (играет Piano Roll) — позиция локальна клипу. `PlayMode::Pattern` — в MVP не поддерживаем, выводим сообщение.

### Этап 3. Клавиатура с подсветкой нажатий — ✅ (2026-10-28)

**Итог:**
- **MIDI-вход:**
  - ~~свой `MidiPort` в режиме Input, выбор устройств через `MidiPortMenu`~~ — заменено 2026-10-29: KeyFall слушает `midiNoteOn/Off` всех инструментальных треков (`Qt::DirectConnection`), одна и та же клавиша с нескольких треков засчитывается один раз; в тулбаре вместо меню «MIDI in» надпись с треками, у которых включён MIDI-вход;
  - время ставится через `steady_clock` в потоке, где пришла нота;
  - note-on с velocity 0 считается отпусканием.
  - **Отличие от плана:** вместо lock-free SPSC-кольца очередь под мьютексом. Разные MIDI-бэкенды вызывают колбэки из разных потоков, то есть производителей несколько. Аудиопоток очередь не трогает, поэтому короткий мьютекс допустим. Размер очереди ограничен 4096 событиями.
- **Ядро без Qt** (`plugin/core`):
  - свой разборщик JSON с номером строки и столбца;
  - `KeyboardLayout`: `format: 2`, сокращение `piano`, генераторы `piano`/`grid`, миграция v1, обратный индекс, `controlForInput` с фильтром канала, `lane()`, `Diagnostic` с кодами E000–E015 и W001–W003;
  - `InputResolver` → `PressEvent`.
- **Раскладки:**
  - встроенные `generic-25/32/37/49/61/76/88` (CC0), вшиты в ресурсы плагина;
  - пользовательская папка `<working dir>/keyfall/layouts/`; файл с тем же `id` перекрывает встроенный, битые файлы показаны серыми с причиной во всплывающей подсказке;
  - выбор раскладки в тулбаре, в меню ⚙ «Open layouts folder» и «Reload layouts»;
  - по умолчанию `generic-61`.
- **`KeyboardWidget`:**
  - рисует любую раскладку через `controlRect()`: фортепиано растягивается по полосе, пэды сохраняют пропорции;
  - статичная часть в кэш-`QPixmap` с учётом DPR;
  - подсветка нажатий; чёрные клавиши перерисовываются поверх подсвеченных белых.
- **Тулбар:** последнее MIDI-событие (нота / CC, канал, «outside layout»). Подсказки в пустых состояниях: «нет устройств», «вход не выбран».
- **Для авторов:**
  - `docs/KEYBOARD_LAYOUTS.md`, `docs/keyboard-layout-2.schema.json`;
  - `scripts/validate_layouts.py` и `tools/kflayout-lint.cpp`;
  - общий набор тестовых файлов `tests/layouts/{valid,invalid}`; ожидаемый код записан в имени файла (`E012-*.json`).
- **Тесты:** `scripts\lmms.cmd test` — 5 наборов (unit, набор файлов на C++ и на Python, встроенные раскладки на C++ и на Python), всё зелёное.

- **Проверено пользователем:** подсветка при игре через `virtual_player.py` и переключение раскладок. Звук трека не меняется; если трек молчит после старта, это автоназначение MIDI в LMMS (см. §6). Баг «раскладки не переключаются» исправлен: связи сигналов перенесены в `modelChanged()`.

**Готово, когда** нажатия на MIDI-клавиатуре подсвечиваются без заметной задержки, а звук в LMMS идёт как раньше.

### Этап 4. Падающие ноты — ✅ (2026-10-28)

**Итог:**
- **Выбор клипа:** в выпадающем списке «трек › клип (такты)» показаны только клипы инструментальных треков. Список перестраивается при каждом открытии: у LMMS нет сигнала «клип добавлен или перемещён», поэтому отдельная кнопка ⟳ не нужна. При `dataChanged`, `lengthChanged` и `positionChanged` клипа ноты перестраиваются. При `projectLoaded` выбор сбрасывается.
- **`core/Chart`** (с тестами):
  - правила видимости нот те же, что в `InstrumentTrack::play()`: учитываются обрезанные края клипа (`startTimeOffset`);
  - наложения нот одной высоты укорачиваются, точные дубли выбрасываются, ступенчатые ноты и ноты нулевой длины получают минимальную длину;
  - `firstVisible()` ищет первую видимую ноту двоичным поиском;
  - `autoKeyRange()` считает диапазон для раскладки **Auto (fit to the clip)**, которая для новых установок стоит по умолчанию.
- **`core/PlayheadClock`** (с тестами): между обновлениями LMMS позиция досчитывается по системным часам. Позиция не идёт назад. При перемотке, на стыке лупа и при большом расхождении она сразу перескакивает. Экстраполяция ограничена 100 мс. Сброс по `playbackPositionJumped` и `playbackStateChanged`.
- **`KeyFall::sampleTransport()`:**
  - читает режимы Song и MidiClip (Piano Roll); дробная часть тика берётся из `frameOffset`;
  - поправка на задержку — один буфер;
  - **отличие от плана:** воспроизведение из Pattern Editor пока не поддерживается, вместо нот выводится объяснение.
- **`FallCanvas`:**
  - ось в тиках, поэтому при автоматизации темпа меняется только скорость прокрутки;
  - линия попадания, сетка тактов и долей с номерами;
  - прозрачность нот зависит от velocity; звучащие сейчас ноты подсвечены;
  - Ctrl+колесо меняет, сколько секунд видно вперёд (1,5–8 с, значение сохраняется);
  - «призраки» нажатий живут по системным часам, поэтому работают и при остановленной песне;
  - надписи «клип начнётся через N тактов», «конец клипа» и «N нот вне раскладки».
- **Клавиатура:** у клавиш, которые звучат сейчас, появляется жёлтая полоса «играй».
- **Тестовый проект:** `scripts/make_test_song.py` создаёт `dev/test-song.mmp` («Ода к радости» + аккорды). Важная деталь: LMMS сдвигает ноты файлов версий до 1.3 на октаву (`upgrade_extendedNoteRange`), генератор это учитывает.
- **Отложено в этап 5:** отметка «пропущено» для нот до точки старта; её делает оценщик.
- **Не проверено:** плавность при автоматизации темпа и на стыке лупа (логика покрыта тестами `PlayheadClock`, глазами не смотрели).

**Готово, когда** полосы плавно ложатся на клавиши ровно в момент звучания ноты в LMMS. Проверено пользователем на тестовом проекте.

### Этап 5. Оценка точности — ✅ (2026-10-28)

**Итог:**
- **`core/Scorer`** (с тестами; всего 517 проверок ядра):
  - окна попадания = `clamp(доля доли × длительность доли, min, max)` по таблице §5 для Loose, Normal и Strict;
  - нажатие засчитывается самой ранней не оценённой ноте этой высоты в окне (FIFO);
  - аккорды (начала в пределах 30 мс): высота оценивается по каждой ноте, ритм — по среднему началу аккорда;
  - соседняя клавиша в пределах 30 мс от верной считается задетой, но не штрафуется;
  - ноты до точки старта получают `Skipped`;
  - итоги: `Notes = попадания / (ожидаемые + 0.5·лишние)`, `Rhythm` = средний кредит аккордов, `Итог = 0.6·Notes + 0.4·Rhythm`, 1–3 звезды, среднее смещение и σ, тепловая карта по тактам песни.
- **Прогоны:**
  - прогон начинается по Play, перемотка или стык лупа начинают новый (стык ловится и по движению позиции назад);
  - прогон заканчивается по Stop или в конце клипа; если песня играет дальше, итог остаётся на экране до перемотки или Stop;
  - время нажатия пересчитывается на шкалу клипа от момента текущего кадра, минус откалиброванная задержка.
- **Обратная связь:**
  - клавиши: зелёная — попадание, красная со штриховкой — лишняя нота (различимо не только цветом);
  - ноты в водопаде: зелёные — сыграны, серые — пропущены;
  - HUD в тулбаре: точность, серия, рано/поздно по последним 8 попаданиям;
  - итоговая карточка: Notes, Rhythm, звёзды, отзыв о времени простыми словами («стабильно поздно на N мс — перекалибруйте» / «неровный пульс» / «по центру»), тепловая карта по тактам, подсказка, если не пришло ни одного нажатия.
- **Калибровка:**
  - пункт ⚙ → Calibrate latency…: 4 удара отсчёта и 16 ударов на 100 BPM, только визуально;
  - медиана после отбрасывания выбросов за 2σ, ручная правка ±300 мс, значение сохраняется в `keyfall/inputoffset`;
  - **отличие от плана:** задержка общая, а не своя для каждого устройства.
- **Встроенный исполнитель ⚙ → Auto-play (demo):** KeyFall сам играет клип синхронно с воспроизведением, с разбросом ±25 мс, 5% неверных клавиш и 5% пропусков. Это и демо, и самопроверка без клавиатуры.
- **Проверено пользователем на тестовом проекте с Auto-play:** Notes 96%, Rhythm 96%, ★★★, «timing centred ±23 ms», тепловая карта отражает пропуск.
- **Не проверено:**
  - калибровка (нет MIDI-клавиатуры, а скрипт не может нажимать в такт анимации);
  - переключение Loose/Strict на живом прогоне (окна покрыты тестами).
- **Не сделано из плана этапа:**
  - подсказка «аккорд арпеджирован»;
  - горячие клавиши окна (`H`, `R`, `C`);
  - стрелка рано/поздно (вместо неё текст).

**Готово, когда** после проигрывания клипа выводятся Notes %/Rhythm %/смещение, а тесты scorer проходят.

### Этап 6. Режимы занятий — ✅ (2026-10-29), руки отдельно отложены

**Итог:** панель занятий под тулбаром. Режимы работают на **собственных часах KeyFall** (`core/PracticeClock`, с тестами), транспорт LMMS стоит. Нажатие Play в LMMS останавливает занятие.

1. **Wait mode** ✅ — `core/WaitGate` (с тестами):
   - время стоит на аккорде, пока не нажаты все его клавиши; клавиши аккорда подсвечены всё время ожидания;
   - считаются пройденные аккорды и неверные клавиши; итог — «Chords X / Y, Clean N %» и совет, что делать дальше;
   - режим «новичок» — галочка **Any note**: чтобы пройти аккорд, хватает любой его ноты;
   - проверено пользователем с Auto-play (15 / 15, Clean 80 %).
2. **Луп по тактам** ✅ — номера тактов песни, границы по умолчанию взяты из клипа, каждый проход оценивается отдельно.
   - **Отличие от плана:** луп в собственных часах, а не через точки лупа LMMS (`Timeline` не экспортирован, и так не нужно трогать проект).
   - Проверено пользователем вместе с кликом метронома.
   - Клик по такту на тепловой карте итоговой карточки сразу запускает занятие с лупом этого такта.
3. **Темп %** ✅ (25–100 %, шаг 5 %): окна попадания растут вместе с долей. **Auto** ✅ (`core/TempoCoach`, с тестами): в лупе после двух проходов ≥ 90 % темп растёт на 5 %, после двух < 70 % падает на 5 %. В строке состояния: «last pass 92 % → tempo 65 %».
4. **Руки отдельно** — отложено по решению пользователя (2026-10-29). Ядро уже готово: `Scorer::start` и `WaitGate::reset` принимают маску активных нот; нажатия нот другой руки не штрафуются (`PressResult::Kind::Ignored`); есть тесты. Осталось сделать интерфейс: точку разделения или руки по трекам, цвета по рукам.
5. **Отсчёт и метроном** ✅: такт отсчёта с кликами и клик на каждую долю. Сэмплы и `SamplePlayHandle` те же, что у Tap Tempo. Пока часы стоят на аккорде, кликов нет.

Настройки панели (кроме границ лупа) сохраняются в конфиге LMMS. Auto-play в режиме ожидания «находит» аккорд через 0,25 с и иногда сначала ошибается клавишей.

### Этап 7. Кнопочные инструменты (v2 раскладок, §3a)

**Шаг 1 — формат и англо-концертина ✅ (2026-10-29), проверено пользователем:**
- **Формат:**
  - `requires` теперь принимает `states` и `rows`;
  - `states` — одно состояние (мех) с одним источником: `inferred` / `cc` + `ranges` / `channel` / `manual`;
  - зона `rows` — смещённые ряды кнопок, ноты задаются списком или отдельно для каждого состояния, `null` означает беззвучную кнопку;
  - новые коды ошибок E016 (ноты по состояниям), E017 (объявление `states`), E019 (зона `rows`); E012 теперь означает неизвестную возможность, второе состояние, `hex` или аккордовые кнопки;
  - оба валидатора, схема, общий набор тестовых файлов и инструкция обновлены.
- **Ядро:**
  - у кнопки своя нота для каждого состояния (`Control::statePitches`, `pitchIn`);

- **Окно:**
  - на кнопках две подписи (сжим сверху, разжим снизу), подпись текущего направления ярче;

## 3a. Раскладки инструментов (расширяемые)

Раздел сведён из четырёх обзоров: архитектура формата, UI/UX, педагогика кнопочных инструментов и существующие решения (2026-10-28).

**Задача.** MIDI-контроллеры бывают очень разными, и KeyFall должен рисовать любой из них по файлу, который может прислать кто угодно, без правок C++:
- клавиатуры на 25–88 клавиш с разной нижней нотой, с пэдами и с кнопками сдвига октавы;
- изоморфные сетки и шестиугольные контроллеры: Launchpad, Linnstrument, Lumatone, Jankó;
- кнопочные инструменты. У MIDI-концертины две шестигранные половины со смещёнными рядами. Англо-концертина и диатонический баян **бисоничны**: одна кнопка даёт разные ноты на сжим и на разжим меха. Хроматический баян B/C повторяет ряды, и одна нота сидит на нескольких кнопках. Бас Stradella — кнопка-аккорд.

**Главный принцип.** На фортепиано сыгранная нота — это высота. На кнопочном инструменте это «кнопка + направление меха». Первый выпуск остаётся только для фортепиано, но его модель данных не должна считать, что цель — это просто MIDI-высота.

**Готового стандарта нет.** Ни один формат не описывает одновременно геометрию кнопок и раскладку нот: Lumatone `.ltn` даёт только назначения без геометрии, профили MIDI 2.0 геометрию не описывают. Поэтому формат свой, но имена полей и приёмы взяты у существующих проектов (см. таблицу ниже).

### Формат `*.kflayout.json` (сразу `format: 2`)

Версия 1 нигде не публиковалась, поэтому выпускаем сразу v2. Файлы v1 принимаются через `migrateV1()`.

**Модель данных:**
- **Layout:** `id`, `name`, `author`, `license`, `match`, `units`, `states`, `input`, `scoring`, `view`, `zones[]`.
- **Zone** — физическая часть инструмента: клавиатура, левая половина, правая половина, бас. У неё есть `hand` (`left`/`right`/`none`) и фильтр канала в `input`. Кнопки зоны задаются **генератором** (`piano`, `grid`, `hex`, `rows`) или **явным списком** `controls[]`. Любая зона превращается в один и тот же список Control.
- **Control** — кнопка или клавиша:
  - `id` (по умолчанию генерируется, например `L.r0.c3`);
  - геометрия: `shape`, `x`, `y`, `w`, `h`, `rot`;
  - `role`: `main` | `helper` | `chord` | `counterBass` | `air`;
  - `label`, `tab` (строка табулатуры);
  - `notes`.
- **`notes`** записывается одинаково везде:
  - `60` — одна нота;
  - `[48, 52, 55]` — аккорд;
  - `{"push": 60, "pull": 62}` — нота зависит от состояния.
- **States** (состояния) объявляются в файле один раз. Там же указано, как определять состояние по MIDI:
  - по контроллеру: `{"cc": 11, "ranges": {...}}`;
  - по каналу: `{"channel": {...}}`;
  - выводом из высоты ноты: `"inferred"` — у бисоничных инструментов пара «канал + нота» часто однозначно указывает на кнопку и направление;
  - вручную: `{"manual": true}`, переключателем в окне.
- **`input`** описывает возможности устройства. Это решает больше всего:
  - `mode: "pitch" | "control"`. Почти все MIDI-концертины и баяны сами учитывают мех и шлют **итоговую высоту**, а не номер кнопки.
  - каналы по секциям (у Roland FR: правая клавиатура 1, бас 2, аккорды 3);
  - `pressureCC` — давление меха, обычно CC7 или CC11.
  - Скорость нажатия (velocity) у таких инструментов часто бессмысленна, по ней не оцениваем.
- **Сдвиг октавы** (`octaveShift`) — это не состояние, а сдвиг на полутоны, чтобы таблицы нот не размножались.
- **Обратный индекс** «высота → кандидаты (кнопка, состояние)» связывает многие-ко-многим. Он покрывает дубли рядов, одну ноту на сжим и разжим, чередование рук у дуэтных концертин.

**Простое остаётся простым:**
```json
{"format": 2, "id": "generic-49", "name": "Generic 49-key", "piano": ["C2", "C6"]}
```
```json
{"format": 2, "id": "launchpad-like", "name": "8x8 pads",
 "zones": [{"type": "grid", "rows": 8, "cols": 8, "origin": 11, "colStep": 1, "rowStep": 10,
            "rowOrder": "bottomUp", "shape": "roundRect", "input": {"channel": 1}}]}
```
```json
{"format": 2, "id": "anglo-20-cg", "name": "Anglo 20 C/G", "units": "mm", "license": "CC0-1.0",
 "requires": ["states", "rows"],
 "states": {"bellows": {"cc": 11, "ranges": {"push": [0, 63], "pull": [64, 127]}, "default": "push"}},
 "scoring": {"match": "noteAndState"},
 "zones": [
  {"id": "L", "hand": "left", "type": "rows", "shape": "circle", "size": 14, "pitch": 18, "stagger": 9,
   "rows": [{"notes": {"push": [48, 52, 55, 60, 64], "pull": [55, 59, 62, 65, 69]}},
            {"notes": {"push": [55, 59, 62, 67, 71], "pull": [62, 66, 69, 72, 76]}}]},
  {"id": "R", "hand": "right", "type": "rows", "shape": "circle", "size": 14, "pitch": 18, "stagger": 9, "origin": [150, 0],
   "rows": [{"notes": {"push": [67, 72, 76, 79, 84], "pull": [71, 74, 77, 81, 83]}},
            {"notes": {"push": [74, 79, 83, 86, 91], "pull": [78, 81, 84, 88, 90]}}]}]}
```

**Генераторы:**

| Генератор | Для чего | Параметры и источник |
|---|---|---|
| `piano` | клавиатуры | диапазон; геометрия клавиш стандартная |
| `grid` | Launchpad, Linnstrument (`rowStep: 5`) | `origin`, `colStep`, `rowStep` или явный список `notes[]` |
| `hex` | Jankó, Wicki-Hayden, Hayden, баян B/C, Lumatone | `origin`, шаги по осям, `stagger`. Шаги изоморфных систем берём как факты: Wicki-Hayden (2,−7), Harmonic Table (−7,3), Jankó (1,−2), баян C (2,−3), баян B (1,−3) |
| `rows` | концертины, Stradella | смещённые ряды со списками нот. По образцу MIT-проекта accordion-trainer: `start`, `count`, `step`, `yOffset`, `role` |

**Совместимость версий.** Новые возможности объявляются в `requires: [...]`. Если файлу нужно то, чего KeyFall ещё не умеет, пользователь увидит понятную ошибку «нужна версия KeyFall ≥ x.y», а не криво нарисованную раскладку. Неизвестные ключи дают предупреждение, не ошибку.

### Оценка точности на нефортепианных инструментах

Политика оценки `scoring.match` задаётся для раскладки или зоны, пользователь может её переопределить.

| Политика | Что сравнивается | Когда |
|---|---|---|
| `note` | только высота и время; любая кнопка-кандидат засчитывается | MVP, по умолчанию |
| `noteAndState` | ещё и направление меха в момент нажатия | v2 |
| `control` | ещё и конкретная кнопка: нужна аппликатура в клипе и устройство, которое сообщает кнопку | later |

**Уровни результата** (список категорий открытый):
- **точно** — нужная кнопка и нужное направление;
- **альтернатива** — та же высота на другой кнопке или в другом направлении. Это нейтральная пометка, а не ошибка, пока урок не фиксирует аппликатуру;
- **ошибка меха** — кнопка та, направление нет. Сообщаем так, потому что исправлять надо руку на мехе, а не палец;
- **неверно**.

**Правила для кнопочных инструментов:**
- **Аккорды на бисоничных инструментах.** Одновременные ноты обязаны совпадать по направлению меха, иначе аккорд «невозможен», а не «частично верен».
- **Stradella.** Кнопку-аккорд оцениваем как одну цель по классу высоты (`pitchClass`) — басовые голоса у разных баянов звучат в разных октавах. Основной бас и контрбас для одного класса высоты взаимозаменяемы.
- **Смена меха** — часть ритма. Её время оценивается как начало ноты, со своим окном попадания: датчики меха дают задержку. Это v2.
- **Повторное нажатие при смене меха.** Некоторые инструменты шлют note-off и сразу note-on, хотя кнопка не отпускалась. Это не новое нажатие.
- **Мелизмы** (форшлаги, cuts, rolls). У нот есть флаг `ornament`: такие ноты не штрафуются по времени и не входят в процент по умолчанию. Есть опция «игнорировать неразмеченные ноты короче X мс». Это v2.
- **Покрытие.** При загрузке клипа ноты, для которых в раскладке нет кнопки, помечаются «неиграбельные на этом инструменте»: они серые и не оцениваются. Процент покрытия показываем. Это MVP.

**Аннотации нот.** Ноты LMMS не умеют хранить свои атрибуты, поэтому KeyFall хранит их сам:
- поля: `buttonId`, `direction`, `hand`, `finger`, `ornament`, `role`, `fingeringLocked`;
- после правки клипа аннотации перепривязываются по позиции и высоте, а потерявшие ноту отмечаются предупреждением;
- откуда брать: каналы по половине инструмента или по направлению меха, текстовые маркеры MIDI, позже ABC/MusicXML;
- если аппликатуры в клипе нет, v2 **подсказывает** её кратчайшим путём (Viterbi) со штрафами за смену меха и переходы между рядами. Подсказку всегда видно как «suggested», и по ней никогда не снижаем оценку.

### Отображение (v2)

Падающие полосы в обычном виде опираются на линейную ось высоты, а у двумерной раскладки такой оси нет.

**Рекомендуемый вид — гибрид (UX):**
- **Лента времени** горизонтальная, по дорожке на руку или половину инструмента. На ней видны ритм, длительности, полоса направления меха и метки кнопок на «фишках» нот. Технически это тот же водопад, повёрнутый на 90°.
- **Карта кнопок** ниже, обе половины в виде **со стороны игрока**, переключатель «Зеркально». На карте сжимающиеся кольца примерно на долю вперёд и живые нажатия.

**Альтернатива (преподаватель):** вертикальная дорожка на каждую кнопку, по половинам, потом по рядам. Её проще читать на темпе, и она почти даром получается из кода водопада. **Решение:** делаем оба вида как режимы отображения, по умолчанию гибрид, и сравниваем на живых пользователях. Режим «только карта» (кольца) — для продвинутых игроков и пэдов.

**Мех:**
- «сжатие» и «разжатие» отличаются цветом **и** формой: сплошная заливка против штриховки, значки ▸◂ / ◂▸;
- смена направления видна за 1 долю, считается в долях, не в мс;
- одна полоса направления общая для обеих рук.

**Альтернативные кнопки:** рекомендуемая кнопка обведена полностью, остальные пунктиром.

**Подписи** переключаются клавишей `L`: номер кнопки (по умолчанию), нота, табулатура, пара «сжатие / разжатие», выключено. Для новичков подпись нотой по умолчанию выключена, чтобы не приучать «искать высоту».

**Табулатура** берётся из нейтрального `buttonId`, конкретные стили табулатуры — сменные отрисовщики (later):
- англо: в стиле Gary Coover / плагина MuseScore — кнопки 1–5, 6–10, 1a/1b, у правой руки точка, разжатие с подчёркиванием;
- мелодеон: внутренний и внешний ряд плюс отметка направления.

Раскладки C/G и G/D дают одну и ту же табулатуру: это транспозиция, а не другая раскладка. Системы B и C — разные раскладки.

### Режимы занятий, специфичные для гармоник (v2)

- одна половина инструмента за раз — это существующее разделение рук, но по половинам;
- режим ожидания, который проверяет ещё и направление меха;
- **тренировка смен меха** — самый полезный режим: автоматический луп вокруг каждой смены, медленно, с постепенным ускорением;
- «только мех», если у инструмента есть датчик;
- упрощённая версия: только мелодия, без украшений и аккомпанемента.

### Код

Ключевое решение для MVP: **фортепиано — это просто сгенерированная раскладка**. Каждая клавиша — кнопка с одной нотой и без состояния. Поэтому:

- **`core/KeyboardLayout`** (чистый C++):
  - `fromJson`, генераторы, `validate`, `migrateV1`;
  - `candidates(pitch)`, `sounding(control, state)`, `controlForInput(ch, note, state)`, `laneX(pitch)`;
  - `StateTracker` для состояний — v2;
  - собственный крошечный `kf::json::Value`, чтобы разбор и проверку можно было тестировать без Qt.
- **`InputResolver`** превращает сырой MIDI в `PressEvent {controlId?, pitches, state, hand}`. Для фортепиано `controlId = pitch`.
- **`TargetEvent {t, dur, pitches[], hand, controlId?, state?, alts[], ornament, role}`** — цель задаётся **множеством допустимых вводов**, а не одной высотой. Рука хранится в ноте, а не вычисляется по точке раздела.
- **Отображение:** `InstrumentView` с методом `controlRect(id)`. Водопад берёт x у раскладки (`laneX`) и ничего не знает про «ноту = x». `PianoKeyboardView` — MVP, `ButtonMapView` и `RibbonView` — v2.

**Проверка файлов:**
- `docs/keyboard-layout-2.schema.json` задаёт структуру;
- смысловые правила имеют стабильные коды (`E012` и т. п.) и описаны в `docs/KEYBOARD_LAYOUTS.md`;
- **общий набор тестовых файлов**: `layouts/tests/valid/*`, `layouts/tests/invalid/E0xx-*.json` с `"$expect"`. Его прогоняют и C++-линтер `kflayout-lint`, и `scripts/validate_layouts.py`; расхождение валит CI;
- сообщения об ошибках: `Diagnostic {severity, code, jsonPointer, message}`. Неверный пользовательский файл серый в списке, причина — во всплывающей подсказке. Если пользовательский файл с `id` встроенного неверен, используется встроенный.

### Где лежат раскладки, лицензии, вклад

- **Встроенные:** `plugin/layouts/`, вшиты как ресурсы. **Пользовательские:** `<рабочая папка LMMS>/keyfall/layouts/`, перекрывают встроенные по `id`.
- Встроенные раскладки распространяются под **CC0**, чтобы ими можно было свободно делиться; у присланных указывается `license`.
- **Источники данных для встроенных раскладок:**
  - **можно брать с атрибуцией:** `mccalluc/concertina-helper` (MIT: англо 20, Jeffries 30, Wheatstone 30) и `JyarlJung/accordion-trainer` (MIT: хроматический баян, Stradella для Roland FR);
  - **только как факты, без кода:** HexBoard (GPLv3);
  - **не копировать:** anglo-piano, anglo-tab и другие репозитории без лицензии. Раскладки выводить заново из фактов (соответствие кнопок нотам не охраняется авторским правом).
- **Мастер «Создать раскладку»** (v2): шаблон → нажать кнопки по порядку (для бисоничных — второй проход на разжатие) → расставить на холсте с привязкой → тест-драйв через настоящий оценщик → сохранить или поделиться.
- Инструкция `docs/KEYBOARD_LAYOUTS.md`:
  - как узнать ноты и каналы (окно показывает последнее MIDI-событие);
  - справочник полей и примеры;
  - валидатор;
  - чек-лист PR.

### Близкий аналог

Это тренажёр с падающими нотами для Roland V-Accordion: JSON-раскладки рядов и Stradella, список кандидатов на каждую ноту (основные ряды раньше вспомогательных), бас оценивается по классу высоты. ## 4. Что берём у существующих решений

Похожих плагинов, форков или запросов для LMMS не найдено — по issues и PR ничего нет, Discussions не проверены.

| Откуда | Что берём (идеи, не код, если не указано иное) |
|---|---|
| **LMMS** (GPLv2+, код можно) | Шаблон `plugins/TapTempo`, геометрия `PianoView`, `ComboBox`/`ComboBoxModel`, `ConfigManager`, `MidiPortMenu` |
| **Neothesia** (GPLv3) | Матчер на двух картах: ожидаемые ноты и недавние нажатия. Wait mode — часы идут, только пока набор требуемых нот пуст. Визуальный сдвиг `animation_offset` |
| **Linthesia** (GPLv2) | Сканирование отсортированного списка с ранним выходом; состояния нот Playable/Hit/Missed. Окно ±165 мс как ориентир |
| **PianoBooster** (GPLv3) | Группировка аккордов по зазору начал. «≥2 неверных зажатых клавиши блокируют аккорд». Новичок: любая нота аккорда, продвинутый: все. Адаптивный темп. Индикатор точности по принципу «дырявого ведра» |
| **Melodics / Piano Marvel / Flowkey / Synthesia** | Цвета «рано/поздно/точно», серии, 1–3 звезды, руки отдельно, луп, скорость %, необязательная оценка длительности |
| **Rhythm Quest devlog** | Калибровка по медиане тапов, отдельный визуальный сдвиг |

**Чего избегать:**
- копировать GPLv3-код;
- доверять отметкам времени MIDI из LMMS;
- двигать часы суммой дельт кадров вместо позиции транспорта;
- использовать окна чисто в тиках;
- выбирать «ближайшую» ноту при повторах одной высоты;
- выпускать без настройки задержки — все проекты без неё получали жалобы.

## 5. Окна попадания — строгость оценки «Timing tolerance» (по умолчанию Normal)

Это не сложность песни: песню пользователь выбирает сам. Строгость задаёт только ширину окон попадания по времени. Настраивается в меню ⚙, а не в тулбаре.

`window = clamp(доля × длительность_доли_мс, min, max)`, по локальному темпу ноты. Ниже 20 мс не опускаемся: столько съедает джиттер MIDI.

| Уровень | Perfect | Good | OK | Промах дальше |
|---|---|---|---|---|
| Loose | ±1/16 доли, 50–90 мс | ±1/8, 90–160 | ±1/4, 160–250 | 250 мс |
| Normal | ±1/24, 35–60 | ±1/12, 60–110 | ±1/6, 110–180 | 180 мс |
| Strict | ±1/32, 20–40 | ±1/16, 40–75 | ±1/8, 75–120 | 120 мс |

**Подсчёт:**
- `Notes = попадания / (ожидаемые + 0.5·лишние)`.
- `Rhythm` = среднее по попаданиям: Perfect 1.0, Good 0.8, OK 0.5. Промах портит только Notes.
- `Итог = 0.6·Notes + 0.4·Rhythm` → % и 1–3 звезды. Без оценок «F» и без счётчика ошибок в заголовке.
- **Смещение:** среднее со знаком и σ после калибровки. Если |среднее| > 25 мс при малом σ — «торопитесь» или «тянете», либо стоит перекалибровать. Большое σ — «неровный пульс».
- Длительность, velocity и педаль в MVP показываем, но не оцениваем.

## 6. Риски

- **Связи «модель → окно» в плагине теряются.** `Plugin::createView()` вызывает `setModel()` уже после конструктора окна, а `ModelView::setModel()` делает `model->disconnect(widget)`. Поэтому соединения от `KeyFall` к окну подключаются в `modelChanged()`, а не в конструкторе. На этом был баг «раскладки не переключаются».
- **`trackAdded` приходит из конструктора `Track`**, когда объект ещё не `InstrumentTrack`: `dynamic_cast` в обработчике даёт null. Подписка на сигналы трека откладывается через `QTimer::singleShot(0)` (баг «кнопки не загораются» 2026-10-29).
- **Автоназначение MIDI в LMMS ненадёжно при старте.** Шаблон проекта снимает подписку трека на порт, а вернётся она только когда инструмент получит фокус. KeyFall слушает вход сам, но для звука трека пользователю нужно кликнуть в инструмент (см. docs/BUILD.md).

- **API master меняется**: `Song::PlayPos` → `Timeline` и т. п. → пиним коммит; при обновлении сверяем `Song.h`, `Timeline.h`, `MidiClip.h`, `MidiPort.h`.
- **MIDI через треки** (с 2026-10-29, вместо патча `LMMS_EXPORT`): работает, только если у трека включён MIDI-вход; note-off приходит, когда отпущена педаль сустейна; CC не приходят, поэтому источник меха `cc` в LMMS не работает (мех решили не делать). Ноты вне диапазона клавиш трека LMMS не пропускает.
- **Падение при старте**: `MainWindow` вызывает `createView` без проверки на null. Ошибка в дескрипторе роняет LMMS целиком.
- **Задержка зависит от бэкенда** (JACK/ALSA/WASAPI/SDL/PortAudio) → калибровка для каждого устройства обязательна в MVP.
- **Wait mode и транспорт LMMS**: программная пауза из Tool-плагина не проверена → свои часы.
- **Наличие в Piano Roll** (`PlayMode::MidiClip`): заглушённые клипы всё равно играют, координаты локальны клипу — учесть в `TransportClock`.
